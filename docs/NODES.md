# One CLI for running JetCash

Requires Ubuntu/Debian with Python 3.10+ and sudo access when dependencies are
missing. Windows uses Ubuntu under WSL2. Other native operating systems have not
been tested. Python automates the setup; the node, wallet keys, private transactions,
consensus, mining and storage run in the pinned C++ engine.

## First run

```sh
git clone https://github.com/Shubhbhangoo/jetcash.git
cd jetcash
python3 jetcash setup --jobs 2
```

On Windows, use `.\jetcash.ps1 setup --jobs 2` instead. All subsequent examples
also work through `jetcash.ps1`. Setup installs the listed system dependencies,
fetches the locked Monero source/submodules, applies JetCash changes, builds and
tests the engine, creates local configuration, and starts a background node.
Installation may ask for your sudo password. `--no-start` builds without running
the node. Setup never starts mining or creates a personal wallet by itself.

There is currently no published default bootstrap seed. To join a reachable node:

```sh
python3 jetcash setup --peer node.example.org:41080
# If already set up:
python3 jetcash peer add node.example.org:41080
```

The hostname above is a placeholder. Use an actual JetCash node address. A peer
change is saved and the local node is restarted automatically. Wallets and chain
data survive restarts; built-in mining stops and can be started again with `mine`.
`peer list` shows saved peers; `peer remove HOST:PORT` removes one.

Anyone with the sources can run a node independently of the original developer's
PC. At least one reachable peer is needed to join the same network. Inbound router
forwarding is optional for nodes that only make outbound peer connections.
To accept inbound peers, allow TCP 41080 as described in [MAINNET.md](MAINNET.md).
Wallet/daemon RPC should remain local.

## Wallet and payments

```sh
python3 jetcash wallet-create --name default
python3 jetcash address
python3 jetcash balance
python3 jetcash send RECIPIENT_ADDRESS 1.25
python3 jetcash backup
python3 jetcash lock
```

Creation prompts twice for a password of at least eight characters. The encrypted
wallet is generated by the C++ wallet implementation. The CLI prints the address
and recovery phrase to your terminal; record the phrase privately. It does not save
a separate plaintext phrase or password file. `backup` requires the wallet password
before displaying the phrase again. `lock` shuts down the local wallet service.
Unlocking a saved wallet prompts for its password. `--name` selects another wallet.

The wallet RPC service binds only to localhost, uses authenticated HTTP RPC, and
keeps its generated login/configuration files private (mode 600 in mode 700
directories). The service stays unlocked while running; use `lock` when finished.
Node RPC is loopback-only and assumes other processes on your local account are
trusted. No RPC port needs internet exposure for peer participation.

`send` signs and broadcasts the specified private payment. Amounts are parsed as
exact integers with eight decimal places. The CLI prints the transaction ID and
fee, not transaction private keys. Spending needs mature funds and a synchronized
node. No transaction confirmation is implied by successful broadcast.

## Mining

```sh
python3 jetcash mine --threads 1
python3 jetcash stop-mining
```

`mine` creates a receiving wallet interactively if needed, opens it, and starts
RandomX CPU mining with the requested thread count. The node must first synchronize
with a peer. There is no automatic mining during setup or node startup. Coinbase
rewards unlock after 60 blocks; the spending ring requires enough mature outputs.
Mainnet uses the difficulty algorithm; synthetic difficulty is confined to regtest.

## Node lifecycle and diagnostics

```sh
python3 jetcash start
python3 jetcash status
python3 jetcash doctor
python3 jetcash restart
python3 jetcash stop
```

Start and stop are idempotent. Stop authenticates and shuts down the managed wallet
service, then gracefully stops the verified JetCash node. Data is kept. A foreign
service or mismatching genesis on the RPC port is refused. Doctor reports actual
height, peer counts, synchronization and configuration; it does not claim public
reachability from a localhost check. The machine and WSL instance must stay running.
This CLI does not install a service that starts at boot.

## Profiles and storage

Use `--network mainnet|testnet|stagenet|regtest` on managed commands. Mainnet is the
default. Per-profile RPC ports are peer-port +1 (daemon), +2 (ZMQ), +3 (wallet).
Mainnet peer port is 41080; testnet 42080; stagenet 43080; managed regtest 44080.
Advanced raw engine commands remain available via `node`, `wallet`, `wallet-rpc`.

| Location | Contents |
|---|---|
| `~/.cache/jetcash/engine` | Pinned source, builds and license notices |
| `~/.local/share/jetcash` | Chain database and per-profile chain folders |
| `~/.local/share/jetcash/wallets/PROFILE` | Encrypted wallets |
| `~/.local/share/jetcash/.control/PROFILE` | Configuration, service logs and protected RPC credentials |

`JETCASH_HOME` changes the chain/wallet/control root. `JETCASH_ENGINE_DIR` changes
the engine build directory. `JETCASH_PORT_BASE` overrides the profile's four-port
group, useful for isolated instances. These paths must be owned by the operator.
Back up encrypted wallets and recovery phrases; do not publish runtime directories.

## Source distribution

```sh
python3 jetcash package-source
```

This creates `dist/jetcash-source.zip`, a SHA256 sidecar, and an internal file hash
manifest. Only explicitly selected source, tests, documentation and licenses are
included. Wallets, logs, live node state, chain databases, local build reports,
Git credentials and binaries are excluded. The bundle downloads pinned upstream
dependencies at build time; it is not an offline dependency bundle.

JetCash is independently unaudited. An open-source license, passing tests, or an
enabled mainnet profile does not establish production safety or stronger privacy
than its upstream implementation.
